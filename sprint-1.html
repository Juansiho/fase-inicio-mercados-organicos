HU01 - Registrarme con una identificación

IdentificadorHU01
NombreRegistrarme con una identificación
DescripciónComo Usuario quiero registrarme con una identificación única para poder participar en los torneos de MatchPoint.
Paso a paso
  1. El usuario abre el formulario de registro.
  2. Diligencia nombre, identificación, correo y contraseña.
  3. El sistema valida los campos y que la identificación no exista.
  4. El sistema crea el usuario con el rol Usuario.
  5. Se muestra la confirmación y se redirige al inicio de sesión.
Criterios de aceptación
  • La identificación debe ser única; si ya existe se informa sin crear un segundo registro.
  • Todos los campos son obligatorios y cada error se muestra junto a su campo.
  • La contraseña se almacena cifrada, nunca en texto plano.
  • Si la solicitud se envía dos veces (doble clic o reintento), se crea un solo usuario.
  • Al registrarse con éxito se muestra un mensaje de confirmación.

HU02 - Iniciar sesión

IdentificadorHU02
NombreIniciar sesión
DescripciónComo Usuario quiero iniciar sesión con mis credenciales para acceder a mis participaciones y a mi saldo.
Paso a paso
  1. El usuario abre la pantalla de inicio de sesión.
  2. Ingresa identificación y contraseña.
  3. El sistema valida las credenciales.
  4. Si son válidas, abre la sesión y muestra el inicio según su rol.
  5. Si no lo son, muestra un mensaje de error.
Criterios de aceptación
  • Con credenciales válidas se accede al inicio correspondiente al rol (Usuario o Administrador).
  • Con credenciales inválidas se muestra un mensaje genérico, sin indicar cuál dato falló.
  • Un usuario sin sesión no puede abrir pantallas internas; se redirige al inicio de sesión.
  • La sesión expira tras un tiempo de inactividad.

HU03 - Crear un torneo

IdentificadorHU03
NombreCrear un torneo
DescripciónComo Administrador quiero crear un torneo para organizar los eventos deportivos en los que los usuarios harán pronósticos.
Paso a paso
  1. El administrador abre la opción Crear torneo.
  2. Diligencia nombre, deporte, fecha de inicio y fecha de fin.
  3. El sistema valida los datos.
  4. Guarda el torneo con estado Activo.

  • Solo un usuario con rol Administrador puede crear torneos.

  • No se permiten dos torneos con el mismo nombre y las mismas fechas.
  • Al guardar con éxito, el torneo aparece en el listado con estado Activo.

HU04 - Registrar un evento con fecha y opciones de pronóstico

IdentificadorHU04
NombreRegistrar un evento con fecha y opciones de pronóstico
DescripciónComo Administrador quiero registrar un evento dentro de un torneo, con su fecha y sus opciones de pronóstico, para que los usuarios puedan participar antes de su cierre.
Paso a paso
  1. El administrador elige un torneo y pulsa Registrar evento.
  2. Ingresa nombre, fecha y hora de inicio y fecha y hora de cierre de pronósticos.
  3. Elige la modalidad: resultado (local, empate, visitante) o ganador.
  4. Define las opciones según la modalidad.
  5. El sistema valida y guarda el evento con estado Programado.
Criterios de aceptación
  • El evento pertenece a un torneo existente.
  • El cierre de pronósticos debe ser anterior o igual al inicio del evento.
  • La modalidad define las opciones: resultado tiene 3 opciones fijas; ganador tiene 2 o más participantes.
  • El evento se crea en estado Programado y aparece en el torneo.
  • Si falta algún dato se muestra el error y no se guarda nada.

HU07 - Asignar créditos iniciales a un usuario

IdentificadorHU07
NombreAsignar créditos iniciales a un usuario
DescripciónComo Administrador quiero asignar créditos virtuales iniciales a un usuario para que pueda participar en las dinámicas de pronóstico.
Paso a paso
  1. El administrador busca un usuario.
  2. Pulsa Asignar créditos e ingresa la cantidad.

HU09 - Restringir acciones según el rol y los permisos

IdentificadorHU09
NombreRestringir acciones según el rol y los permisos
DescripciónComo Sistema quiero restringir cada acción según el rol del usuario para que solo los autorizados administren torneos, eventos y créditos.
Paso a paso
  1. Se definen los roles Administrador y Usuario.

  • Un Usuario solo accede a sus propias participaciones y movimientos.
  • Una acción no permitida devuelve un mensaje de acceso denegado.
  • La verificación se hace en el servidor, no solo ocultando botones en pantalla.
